# Email assistant and MCP

Configure the AI provider in **Admin → Agent**. Kite supports Cloudflare Workers AI, Anthropic's native API, and OpenAI-compatible providers, including Haimaker.ai, OpenAI, OpenRouter, Groq, and custom endpoints. The Haimaker catalog is fetched from its API, so available models from DeepSeek, Qwen, GLM, Kimi, and MiniMax appear without hardcoded IDs. You can save several providers, each with its own key and models, and switch between them with **Use this provider** without typing anything again; exactly one is in use for every AI feature (see [AI providers](assistant.md#ai-providers)). You can configure multiple models per provider, then choose a model for each mailbox in the assistant's **Settings** view; a mailbox whose model the provider in use does not offer uses that provider's default and says so. Assistant chat is available by default once a provider is configured; an admin can turn it off in **Admin → Agent**. The assistant works within the selected mailbox. Mailbox managers can set instructions for the mailbox (general, chat, drafting and summaries), a draft reviewer, and a daily auto-draft limit; every user can also set their own instructions under **My instructions** (see [Instructions](assistant.md#instructions)). In the composer, **Write with Kite** writes or rewrites the body (see [Write with Kite in the composer](assistant.md#write-with-kite-in-the-composer)). Automatic reply drafts are off until enabled for that mailbox, and a person must review a draft before sending it. **Admin → Agent → View Usage** shows AI request totals, estimated spend, daily usage, and a paginated activity log.

You can follow up on an assistant draft in chat. The assistant can revise its body, subject, sender, recipients, and send time, copy an attachment from an email in the selected mailbox, or remove a draft attachment. It reads the latest draft revision before editing. A requested send time does not queue delivery on its own: the assistant creates a review link, and the user confirms the exact draft and time in Kite. The composer can also edit an assistant draft, add local files, and request the same review. Apply the latest database migration before using scheduled assistant drafts.

Each tool call the assistant makes counts as one step. **Max steps per question**, at the top of the assistant's **Settings** view, sets how many steps it may take for one question; it is a personal setting (default 15, from 3 to 30) and applies to every mailbox you use. Higher limits let it handle bigger tasks but take longer and use more AI quota. On its last allowed step the assistant cannot call tools and must answer with what it has found, saying so if it ran out of steps. The setting is also available as `GET`/`PATCH /api/settings/assistant` with `{ "maxSteps": number }`; the same route reads and saves your own instructions as `{ "instructions": { "general", "chat", "draft", "summary" } }` (all four strings, up to 2,000 characters each).

The read tools are `list_emails`, `search_emails`, `count_emails`, `get_email` and `get_thread`. `count_emails` takes an optional search query (the same syntax as search), folder and read state and returns one exact count, so a question such as "How many GitHub emails are in my inbox?" needs a single step instead of paging through results.

The assistant can also organize mail: `mark_emails_read` and `mark_emails_unread` (up to 20 emails), `move_emails` (archive, trash, spam or back to the inbox, up to 20 emails), `list_folders`, `create_folder` and `move_emails_to_folder` (up to 20 emails into one folder). The older single-email `mark_email_read` and `move_email` still work. In chat these never act on their own: the tool returns a proposal that lists the emails or the folder, and nothing changes until you choose **Approve** under it. To clean up mail matching a search, the assistant searches first and proposes at most 20 emails at a time. Once approved, the card says what changed and offers **Undo**; the change is also recorded in the assistant's **Activity**, where full-access users can undo it for 7 days. Undo puts back only the emails that are still exactly where the action left them (same status, folder and read state), so it never overwrites a later move, filing or read change; when some had changed since, the card says so, for example "Undid 2 of 5; 3 had moved since", and when none could go back the undo is refused. Undo removes a created folder only while nothing is filed in it and no mailbox rule uses it. Undoing a move to or out of Spam puts the email back and also takes back what the spam filter learned from the move, exactly (see [Undoing a report](spam-protection.md#undoing-a-report)); until the database update that records this is applied, undo moves the email back but the filter keeps what it learned. Moves and folders need full access to the mailbox; read state needs only read access, as in the inbox, and someone with read access can undo only their own read-state change. Mail held by the Screener is never listed or changed. The assistant has no separate date tool: every message you send carries the current date and time in your time zone.

While an email from the selected mailbox is open, the assistant shows **Current email:** with its subject above the prompt, and each message you send tells the model which email that is, so "this email" means the one on screen even after the chat has discussed others. Only the email's ID goes with your message, never its subject or text, and the note is not saved in the chat history; the assistant still reads the email with its tools. Kite ignores the ID unless the email is in the selected mailbox and you could read it with `get_email`, so another user's draft in a shared mailbox is never named. Choose **✕** (Don't use this email) to leave the open email out of the chat until you open another one.

While the assistant is responding, you can enter more messages. They appear in a queue above the prompt and run in order after the current response. You can edit or remove a queued message, or choose **Steer** to stop the current response and send that queued message next. Switching chats or closing the assistant clears the local queue.

To connect an external AI client, create a key in **Settings → API keys** and enable **Allow MCP access**. Choose the permitted mailboxes and mail tools. After creation, copy the key or the ready-made AI agent instructions; the key is shown only once. Connect the client to `https://<your-kite-origin>/mcp` using Streamable HTTP and `Authorization: Bearer <key>`. Mail MCP access is limited to the selected mailboxes and the key owner's current permissions. An alias shares its parent mailbox, so selecting that mailbox also includes mail delivered to its aliases. The MCP `request_send` tool creates a review request; sending still requires confirmation in Kite. MCP mail tools do not require an AI provider.

Over MCP the organize tools need the **Organize mail** permission (`mcp:organize`) and `list_folders` needs **Read mail** (`mcp:read`). They act at once, without the chat approval, like the MCP move tools always have, and are not recorded in Activity; they are written to the mailbox audit log like other MCP changes, including a created folder.

MCP clients can use `update_draft` for the same draft fields and attachments, then `request_send` to create a human review for immediate or scheduled delivery. Attachment additions copy an existing file from an email in the key's permitted mailbox; local files are added through the composer.

Calendar access uses separate **Read calendar** and **Manage calendar** MCP permissions. The personal calendar exposes `get_calendars`, `get_schedule`, `search_events`, `get_event`, `find_free_time`, `create_event`, `update_events`, and `delete_events`. Calendar-only keys need no mailbox selection. Calendar writes save immediately. Event updates and deletes use series IDs and affect the entire recurring series; these tools record attendees but do not send invitations or cancellations. Supply absolute ISO 8601 times with offsets. Schedule and availability ranges are limited to 90 days.

For management tools, create a separate MCP key in **Admin → API keys**. Its selected domain, account, and mailbox management permissions do not grant access to mail content. This page also provides copyable AI agent instructions after key creation.
