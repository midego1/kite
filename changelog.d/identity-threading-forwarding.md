### Security

- A received reply joins a conversation only when its sender already takes part in it or the message passed DMARC for its own From domain, so a stranger who learned a Message-ID can no longer slip a message into a conversation; a message whose Message-ID is already a conversation's key starts a new one. Someone newly copied from a domain without DMARC, or a mailing list without DMARC, starts a separate conversation until they are part of it. Mail import, connected accounts and JMAP drafts keep joining as before. Conversations no longer show Spam unless you open that message (upstream Mailflare #223).
- Received mail no longer renames a contact. Every message in the list, the conversation, the reader and the contact card shows the name you saved for the contact, else that message's own From name, else a name learned earlier, so a shared `no-reply` address keeps a different sender per message (upstream Mailflare #223, #226).
- The forwarding loop guard `X-Kite-Forwarded` is now signed with a server secret (`APP_ENCRYPTION_KEY`, else `INBOUND_WEBHOOK_SECRET`, else `CF_TOKEN`), so a sender can no longer switch account forwarding off for its message with `X-Kite-Forwarded: 1`. The pre-rename `X-Mailflare-Forwarded` counts only with the signed value. Installs without any of these secrets keep the unsigned value; set `APP_ENCRYPTION_KEY` to get the signed one. Two installs forwarding to each other stop after one extra hop. See "The forwarding loop guard" in `docs/sending-and-deliverability.md` (upstream Mailflare #223).
- New-mail notifications name the sender as "Name <address>" without control or direction-changing characters, and mail a rule or a block files in Trash no longer notifies, like Spam (upstream Mailflare #223).
- Senders first seen in Spam, Trash or the Screener are no longer looked up on Gravatar (upstream Mailflare #220).
- The `message.inbound` webhook is no longer sent for mail filed in Spam or Trash; mail held by the Screener still sends it (upstream Mailflare #224).
